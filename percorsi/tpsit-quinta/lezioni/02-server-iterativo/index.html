Un server che non si ferma

Connessione persistente, cicli e server iterativo.

Durata: 1 ora Strumenti: Python, Telnet e due terminali Prerequisito: Lezione 1 Rete: solo questo computer

Ripartiamo dall’esperimento

Un solo scambio, poi la fine

Nella Lezione 1 il client riusciva a collegarsi, il server riceveva un messaggio e inviava la risposta. Subito dopo, però, la connessione veniva chiusa e per una nuova prova dovevamo riavviare il server.

?

Domanda-problema

Perché Telnet viene disconnesso dopo il primo scambio di dati?

Seguiamo il flusso del programma precedente:

socket()
   ↓
bind()
   ↓
listen()
   ↓
accept()
   ↓
recv()
   ↓
sendall()
   ↓
fine

Il programma arriva semplicemente alla fine: nessuna istruzione gli dice di tornare indietro.

Al termine

Che cosa saprai osservare

Dialogo persistente

Riconoscere il ciclo che permette allo stesso client di inviare più messaggi.

Disconnessione

Individuare il valore b'' e usare break per terminare il dialogo corrente.

Client in successione

Spiegare perché il server torna ad accept() e serve un nuovo client alla volta.

Un tentativo da capire

Richiamare main() non significa “ricomincia”

Un’idea possibile è richiamare la funzione alla fine del programma:

def main():
    ...
    main()

La nuova chiamata parte prima che la precedente sia terminata. Le chiamate si accumulano una dentro l’altra:

main()
  └── main()
       └── main()
            └── main()
                 ...

Parole nuove

Ricorsione

Una funzione richiama sé stessa. È un meccanismo utile in altri problemi, ma non è ciò che ci serve per mantenere vivo questo server.

Iterazione

Un blocco di istruzioni viene ripetuto da un ciclo. Qui ripetiamo soltanto le operazioni necessarie al dialogo.

i
Se vogliamo ripetere delle istruzioni, non dobbiamo richiamare tutto il programma.

Possiamo ripetere soltanto la parte che ci interessa con un ciclo.

Primo passo

Manteniamo aperto il dialogo

Partiamo dal server della Lezione 1 e ripetiamo la ricezione mentre il client rimane collegato.

import socket

HOST = "127.0.0.1"
PORT = 50000

def main():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
        server.bind((HOST, PORT))
        server.listen(1)

        print(f"Server in ascolto su {HOST}:{PORT}")

        conn, addr = server.accept()

        with conn:
            print("Client connesso:", addr)

            while True:
                dati = conn.recv(1024)

                if not dati:
                    break

                messaggio = dati.decode().strip()
                print("Ricevuto:", messaggio)

                risposta = "Hai scritto: " + messaggio
                conn.sendall((risposta + "\n").encode())


if __name__ == "__main__":
    main()
while True

È un ciclo che ripete il blocco di istruzioni. Qui mantiene vivo il dialogo: dopo una risposta, il server torna ad attendere altri dati dallo stesso client.

Una sola esecuzione di recv() gestisce un momento del dialogo. Il ciclo permette di eseguirla di nuovo senza chiudere conn.

Quando il client si scollega

Che cosa significa if not dati?

Durante il dialogo, recv() restituisce una sequenza di byte simile a questa:

b'ciao\r\n'

Quando il client chiude correttamente la connessione, recv() restituisce una sequenza vuota:

b''

Perciò questo controllo rileva la chiusura:

if not dati:
    break
il client si è disconnesso
        ↓
termina il ciclo di dialogo

Il peer è il programma all’altro capo della connessione: in questo caso, il client Telnet. break interrompe il ciclo interno. Uscendo dal blocco with conn:, la connessione viene chiusa.

Esperimento con Telnet

Più messaggi, stessa connessione

  1. Terminale 1: avvia il server.
    python server.py

    Se necessario, usa py server.py.

  2. Terminale 2: collega Telnet.
    telnet 127.0.0.1 50000
  3. Invia almeno tre messaggi.
    ciao

La differenza fondamentale

Adesso lo stesso client può inviare più messaggi senza essere disconnesso dopo la prima risposta.

Abbiamo davvero risolto tutto?

Dopo Telnet termina anche il server

Chiudi Telnet. Su Windows puoi premere Ctrl+], scrivere quit e premere Invio. Il ciclo di dialogo termina, ma anche il programma server arriva ancora alla fine.

?

Seconda domanda-problema

Come permettiamo a un nuovo client di collegarsi senza riavviare il server?

Dobbiamo ripetere anche accept(): serve un secondo ciclo, più esterno.

Secondo passo

Un server iterativo

Scarica il programma completo oppure ricostruiscilo aggiungendo il ciclo esterno.

Scarica server.py
import socket

HOST = "127.0.0.1"
PORT = 50000

def main():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
        server.bind((HOST, PORT))
        server.listen(1)

        print(f"Server in ascolto su {HOST}:{PORT}")

        while True:
            conn, addr = server.accept()

            print("Client connesso:", addr)

            with conn:
                while True:
                    dati = conn.recv(1024)

                    if not dati:
                        break

                    messaggio = dati.decode().strip()
                    print("Ricevuto:", messaggio)

                    risposta = "Hai scritto: " + messaggio
                    conn.sendall((risposta + "\n").encode())

            print("Client disconnesso")


if __name__ == "__main__":
    main()
Server iterativo

Gestisce un client, termina il dialogo con esso e successivamente ne accetta un altro.

Leggiamo la struttura

Due cicli, due responsabilità

listen() e accept() non fanno la stessa cosa

server.bind((HOST, PORT))
server.listen(1)

while True:
    conn, addr = server.accept()

bind()

Associa il socket server all’indirizzo IP e alla porta scelti.

listen()

Mette quel socket nello stato di ascolto. Nella struttura del nostro programma viene eseguito una sola volta.

accept()

Attende una richiesta di connessione. Per ogni nuovo client restituisce un nuovo socket conn, dedicato a quella connessione, e il relativo indirizzo addr.

Quando il dialogo termina e conn viene chiuso, il socket server è ancora in ascolto: non deve eseguire nuovamente listen(), ma torna alla successiva accept().

!
listen(1) non significa “accetta un solo client e poi smetti”.

Il parametro riguarda le connessioni che possono rimanere in attesa, non il numero totale di client che il server potrà servire durante la sua esecuzione. Per ora ci basta evitare questo equivoco.

Il compito dei due cicli

Ciclo esterno

Gestisce la successione dei client: attende una connessione, poi torna ad accept().

Ciclo interno

Gestisce il dialogo con il client attualmente collegato: riceve, elabora e risponde.

Ora prova tu

Due collegamenti senza riavviare il server

Prodotto atteso: una prova osservabile nella quale il server risponde a tre messaggi, rileva la disconnessione e accetta un nuovo collegamento.

  1. Avvia il server.

    Esegui python server.py in un terminale.

  2. Collega il primo client.

    Apri Telnet e invia almeno tre messaggi.

  3. Chiudi il client.

    Verifica che il server mostri Client disconnesso senza terminare.

  4. Collega un nuovo client.

    Apri nuovamente Telnet e invia un altro messaggio, senza riavviare il server.

  5. Controlla il risultato.

    Il nuovo messaggio deve ricevere una risposta e il server deve restare in esecuzione.

Sfida facoltativa — risposta in maiuscolo

Sostituisci la costruzione della risposta con risposta = messaggio.upper().

Sfida facoltativa — lunghezza del messaggio

Usa risposta = f"Hai inviato {len(messaggio)} caratteri".

Domanda finale

Il nostro server può servire più client?

Sì, ma uno alla volta. Può accettare più client in successione, non servirli contemporaneamente.

!
Che cosa accade se il primo client rimane collegato e un secondo prova a usare il server?

Il server non può ancora gestire il secondo client: finché rimane nel ciclo interno del primo, non torna a eseguire accept(). La nuova connessione può quindi rimanere in attesa.

Client in successione ≠ client contemporanei. Nelle prossime lezioni vedremo come affrontare questo limite; qui ci fermiamo all’osservazione.

Da ricordare

Il ciclo giusto nel punto giusto

  • accept() attende un client.
  • recv() attende dati.
  • Il while interno mantiene il dialogo.
  • b'' indica che il peer ha chiuso la connessione.
  • break termina il dialogo corrente.
  • Il while esterno permette di accettare il client successivo.
  • Il server realizzato è iterativo, non concorrente.
